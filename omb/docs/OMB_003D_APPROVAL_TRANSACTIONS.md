# OMB-003D b6 结果审批事务

裁决为 `READY_FOR_003D_TRANSACTION_REVIEW`。人工在场平台仍为 `BLOCKED_APPROVAL_PLATFORM`，003E～003G 为 `HOLD`。

## 事务合同

- 可信宿主通道须先确认操作者身份。候选库核对当前的单操作者公钥登记，并拒绝以已有 Bot 或 Service 主体身份准备挑战。挑战绑定工作区、数据库实例、审核版本、固定公钥、决定、幂等键及运行会话。挑战随机值只返回给该通道，数据库保留其 SHA-256。
- 提交在 SQLite `BEGIN IMMEDIATE` 中重新读取并核验授权状态、待审任务及证据链。通过签名和双时钟校验后，同步写入结果决定、唯一的挑战消费记录、任务版本和审计事件。数据库通过决定记录的唯一挑战摘要标记消费。三个结果决定分别进入 `COMPLETED`、`REJECTED` 或 `READY`。
- 同一幂等键重提同一签名内容时，服务验证签名、公钥、数据库实例及历史完整性，返回带 `replayed: true` 的原决定。并发提交最多产生一个决定。首次提交之后新增的撤销事件仍保留，历史回放只表示原决定。
- 审计事件绑定操作者、审核、决定、签名内容与收据指纹。历史验证检查事件、任务版本、领取的挑战和决定记录是否一致。候选库保留决定理由与签名指纹。完整收据、挑战随机值及私钥均未写入数据库。
- 准备接口对已有幂等键返回 `APPROVAL_CHALLENGE_EXISTS`。同一会话内准备响应丢失后的恢复由待验收的可信通道处理。未提交挑战在服务重启后失效。

## 实证与回滚

- MacBook 本机回归 260/260 通过，其中 23 项为本轮专项用例，32 项为来自 OMB-002-FIX 的历史用例。测试使用临时软件密钥及合成证据。
- 将既有 b5 的 D3 开发数据库迁移到单独 D4 文件，通过真实 stdio 与 MCP SDK 验证协议协商、工具发现、创建、幂等查询、读取和异常拒绝。仍发现九项工具。迁移前后 D3 文件哈希相同，四个冻结输入的指纹均匹配。
- 实机非交互诊断报告当前会话无法访问 Secure Enclave 和在场认证，且有效代码签名身份为零。可信原生通道、受保护公钥登记、逐次人员在场和 OpenMausBot 联调仍待实机验证。审批接口继续保持锁定。
- 回滚时关闭 b6 开发进程，使用原 b5 工作目录和原 D3 文件。D4 开发数据库另行保留用于审计。冻结部署沿用其原有启动器及数据库。
