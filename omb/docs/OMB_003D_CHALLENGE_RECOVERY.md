# OMB-003D b7 审批挑战恢复

裁决 `READY_FOR_003D_TRANSACTION_REVIEW`。人工在场审批为 `BLOCKED_APPROVAL_PLATFORM`，003E～003G 为 `HOLD`。

## 恢复规则

- 可信审批组件在同一个服务会话中复用审批事务实例。准备响应丢失时，按原任务、预期版本、决定和幂等键重试，取回原挑战值和原到期时间。
- 挑战值以 HMAC-SHA256 从当前实例的随机内存密钥和已提交的挑战字段导出。字段包括当前服务会话、操作者、固定公钥指纹、待审结果快照、有效期和幂等键。D4 数据库仅保存挑战值的 SHA-256，数据库结构兼容 b6。
- 恢复前重新核验当前证据、授权范围、策略、操作者、公钥及双时钟。请求参数变化时返回幂等冲突。挑战被消费、会话失效或授权变化后拒绝恢复。已经提交的历史决定仍可按既有签名收据回放。
- 审批事务仍只在独立测试中调用。Bot 和 MCP 的审批入口维持锁定，真实原生通道和逐次人员在场尚待验收。

## 测试与回滚

- MacBook 自动化回归 278/278 通过，包括 18 项新增恢复用例及 32 项冻结基线历史用例。专项验证覆盖提交后响应丢失、并发重试、有效期、时钟回退、上下文变更和重启。
- 启动 b6 生成隔离的 D4 合成数据库，再用 b7 打开同一数据库。b7 通过已提交收据回放历史结果，拒绝恢复上次启动的未消费挑战，保留原决定和挑战条目。
- 实际开发 MCP 进程与 SDK 完成协议协商、读取、创建、幂等回放和异常输入检查。四个冻结输入 SHA-256 校验通过。本次非交互诊断仍无法调用在场认证，并报告零个有效代码签名身份。
- 回滚时关闭 b7 开发进程，恢复原 b6 工作目录及其独立数据库。保留 b7 的开发证据用于复核。
