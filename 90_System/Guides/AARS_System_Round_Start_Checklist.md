# AARS_System_Round_Start_Checklist

## 1. Purpose

This checklist provides a practical routine for starting a new bounded AARS system round.

It is intended to:
- prevent vague system-round starts
- ensure the new round begins from a clear anchor
- reduce carry-over confusion from previous rounds
- define what should be explicit before significant system work begins

This is a round-start checklist, not a stage model.

---

## 2. Core Start Rule

A new round should begin only when:

**the prior round’s closure state is clear enough and the new round’s bounded objective is explicit enough**

A new round should not begin only because:
- more ideas exist
- many files still feel incomplete
- the system could always be improved further
- activity wants to continue without re-bounding

---

## 3. Minimum Round Start Checklist

### A. Prior-Round Clarity
- [ ] Is the previous round’s current state clear?
- [ ] Is the latest stable anchor from the prior round explicit?
- [ ] Has the prior round been sufficiently reviewed or closure-noted?

### B. New-Round Identity
- [ ] Does the new round have an identity?
- [ ] Is the round scope explicit?
- [ ] Is this really a new round rather than unfinished previous-round work?

### C. Objective Clarity
- [ ] Is the primary bounded objective explicit?
- [ ] Is the intended outcome explicit?
- [ ] Is the new round’s non-goal or out-of-scope boundary clear?

### D. Priority Clarity
- [ ] Is this round truly the next priority?
- [ ] Is the round justified relative to active projects and current system maturity?
- [ ] Is a more urgent stabilization or recovery step being ignored?

### E. Continuity Readiness
- [ ] Is the prior stable anchor known?
- [ ] Is the next bounded step from that anchor known?
- [ ] Is the new round being opened from a valid baseline?

---

## 4. Start Red Flags

A new system round is probably premature if:

- [ ] the previous round never reached a clear closure judgment
- [ ] the latest stable view is still ambiguous
- [ ] the new round scope is still broad or undefined
- [ ] the new round overlaps heavily with unfinished prior-round work
- [ ] a recovery need exists but is being skipped
- [ ] the round is being opened mainly from momentum rather than bounded need

---

## 5. Start Output States

A round-start review should end with one of the following:

- **Start Approved**
- **Start Approved With Caution**
- **Clarify Previous Round First**
- **Recover / Stabilize Before Start**
- **Do Not Start Yet**

This keeps round initiation governed.
