# AARS_Project_Priority_Board

## 1. Purpose

This page is the project-priority coordination board for AARS.

It is intended to:
- show current project priority ordering
- explain why a project is receiving current effort
- distinguish active effort from frozen or archived reference value
- support bounded multi-project coordination
- provide a practical next-action board for AARS system use

This page is a coordination page, not a governance model.

---

## 2. Use Rule

Use this page when:
- deciding which project should receive attention next
- checking whether a project is active but not currently top priority
- reviewing project workload sequencing
- preventing hidden competition between multiple projects

Do not use this page as a substitute for project charter or local project review notes.

## 5. Priority Logic

Project priority should consider:

1. strategic system value  
2. current project maturity  
3. continuity risk  
4. readiness for bounded completion  
5. whether current work unlocks future reusable system value  

This means priority is not based only on novelty.
