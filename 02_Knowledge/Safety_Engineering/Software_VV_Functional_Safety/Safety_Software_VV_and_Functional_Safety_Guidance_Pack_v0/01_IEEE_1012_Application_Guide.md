# IEEE 1012 Application Guide

## 1. Purpose

This guide explains how to apply IEEE 1012 to safety-related software and digital systems.

## 2. When to use IEEE 1012

Use IEEE 1012 when the task is primarily about:

- V&V planning
- lifecycle V&V coverage
- requirements, design, and implementation review
- verification and validation separation
- independence
- traceability
- anomaly management
- configuration management
- final V&V reporting

## 3. Core distinction

- Verification: did we build it right?
- Validation: did we build the right thing?

Do not collapse these into one activity.

## 4. Typical lifecycle application

1. Define system and software boundary.
2. Define V&V objectives and scope.
3. Define independence and review roles.
4. Review requirements.
5. Review design.
6. Review implementation.
7. Verify integration behavior.
8. Validate intended use.
9. Close anomalies.
10. Issue final V&V summary.

## 5. Required evidence themes

- approved V&V plan
- review records
- traceability records
- test evidence
- validation evidence
- anomaly log
- baseline control records
- V&V summary report

## 6. Common failure modes

- testing treated as full V&V
- validation reduced to FAT or SAT
- weak baseline control
- missing traceability
- no explicit anomaly closure discipline

## 7. Engineering use note

In mixed functional-safety work, IEEE 1012 usually governs the V&V discipline while IEC 61508 or IEC 61511 govern the functional-safety lifecycle logic.
