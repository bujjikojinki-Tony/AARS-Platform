# IEC 61511 SIS Lifecycle Guide

## 1. Purpose

This guide explains how to structure process-industry SIS / SIF work using IEC 61511 logic.

## 2. When to use IEC 61511

Use IEC 61511 when the task involves:

- SIS design or retrofit
- SIF definition
- target SIL assignment
- SRS / SIF SRS generation
- proof test logic
- bypass control
- safety validation
- management of change

## 3. Core rule

A SIS / SIF claim requires lifecycle evidence, not only certified hardware.

## 4. Lifecycle view

1. Establish hazard and risk basis.
2. Identify SIFs.
3. Assign target SIL.
4. Create SRS / SIF SRS.
5. Design sensors, logic solver, and final elements.
6. Verify the loop and logic.
7. Validate the function.
8. Define proof testing.
9. Control bypasses and overrides.
10. Control changes through MOC.

## 5. Evidence themes

- hazard basis
- LOPA or equivalent basis
- SIF statement
- SIL basis
- SRS / SIF SRS
- loop design basis
- proof test basis
- bypass control logic
- validation evidence
- MOC evidence

## 6. Common failure modes

- treating hardware certificates as full SIF evidence
- weak response-time basis
- invisible bypass states
- missing proof-test assumptions
- no MOC trigger for safety-relevant changes

## 7. Engineering use note

IEC 61511 is often the most operational standard for process protection work. Use IEEE 1012 alongside it when the software V&V discipline needs to be made explicit.
